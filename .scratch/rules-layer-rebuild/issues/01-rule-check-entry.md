# 01: 规则检查入口与门禁接线

**What to build:** 一条统一、可重复执行的规则层检查入口。任何维护者执行 `node tasks.mjs check-rules` 都能得到「规则层是否完好」的判定，失败时能立刻知道是哪一条不变量被违反、涉及哪个文件。这个判定同时是默认门禁 `node tasks.mjs check` 的第一步——规则漂移在提交前就被拦住，而不是等到某次审计才发现。检查只读文档与迁移 schema，不连数据库、不连网络。

**Blocked by:** 无（可立即开工）

**Status:** ready-for-agent

- [ ] `node tasks.mjs check-rules` 存在；通过返回 0，不通过返回非 0，并在输出中指明违反的不变量与涉及的文件。
- [ ] `node tasks.mjs check` 的执行序列以规则检查开头（秒级快速失败），tasks.mjs 的帮助文本与该顺序一致。
- [ ] 检查实现与既有检查脚本同组织方式（与 `scripts/db/`、`scripts/ops/` 同级），不引入新的运行时依赖。
- [ ] 骨架为六条不变量各留一个断言位置：尚未实现的断言显式占位为「尚未实现」，不得产生假绿。
- [ ] 在没有数据库与网络的环境下可运行并判定为绿。
- [ ] 有配套单元测试，至少覆盖「全部通过」与「某条不变量被违反时报红并指出文件」两条外部行为。
- [ ] 检查只判定文档层不变量；依赖方向、表归属与接口契约不由本检查判定，仍按现有规则由人工核对。

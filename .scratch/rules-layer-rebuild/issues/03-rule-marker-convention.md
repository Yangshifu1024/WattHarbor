# 03: 规则条目标记约定与可追溯性检查

**What to build:** 规则条目获得统一的可机器解析标记。每条规则要么指向一个真实存在的检查入口，要么原地声明「本条无对应检查」。维护者扫一眼就知道哪条约束是机器在守、哪些靠人盯，agent 也不会把散文误当成有机器保障的约束。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 标记语法在仓库里有唯一说明（人读层一处），并覆盖两种形态：指向检查入口、声明本条无对应检查。
- [ ] 检查能报出三类问题：标记语法非法、标记引用了不存在的检查入口、规则条目缺少标记。
- [ ] 检查入口注册表只有一个落点；注册表与门禁任务清单之间的偏差（新增未登记、登记已不存在）被报出。
- [ ] 检查当前作用域为新层规则文件，对现有文档集合判定为绿。
- [ ] 标记形式在人读层可读：读者不打开检查器源码也能理解每条规则的守护方式。
- [ ] 人读层里对「无法断言化」的规则给出统一写法，不制造第二套标记词汇。

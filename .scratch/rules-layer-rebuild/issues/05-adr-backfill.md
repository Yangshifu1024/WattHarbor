# 05: 回捞架构决策记录

**What to build:** 散落在旧文档里的关键取舍被提炼为编号连续的 ADR，旧文档对应位置改为指向 ADR 的指针。后来者不必翻 615KB 才知道「当初为什么这么定、否决了什么方案」。

**Blocked by:** 02, 04

**Status:** ready-for-agent

- [ ] ADR 总数达到 10–15 条，每条满足三条齐全：难以逆转、无上下文时反直觉、源于真实权衡；不满足的不收。
- [ ] 每条 ADR 写明背景、取舍与代价；被否决的替代方案在有记录价值时保留。
- [ ] 旧文档中对应的长篇论证被替换为指向 ADR 的指针，论证要点不丢失。
- [ ] ADR 编号连续、状态标注齐全，04 的检查判定为绿。
- [ ] 至少覆盖规格点名的候选：部署进程拆分且内部端口两套编排都不映射；后台进程不取微信与支付凭据；真库集成测试单列一层不进默认门禁；白名单常量串不可直接拼进 SQL 的 IN 列表；状态词汇归属领域包而非各用例包。
- [ ] 回捞不新增规则语义：只是把已有理由换个承载方式，说法搬家、内容不变。

# 单体部署复用五个服务的业务边界

小规模环境中，五个独立服务的部署和故障排查成本高于独立扩缩容带来的收益。开发和生产统一运行单体入口，复用五套应用装配，通过进程内 HTTP 传输保持内部契约和服务令牌检查。公开 HTTP 路由只转发用户、后台和公共通知。设备接入使用独立的 TCP 监听生命周期。

新部署可使用同一个 MySQL schema。业务 Outbox 和设备 Outbox 使用不同表名，保留各自的事件来源、幂等键和 Redis Stream 契约。既有数据可继续部署在三库，便于将运行拓扑切换与数据迁移分开验证。

单体共享进程故障范围。运行异常需要整进程恢复，所以端口绑定、依赖检查、任务停止和数据库资源释放都由单体入口统一管理。开发保留三库和原有数据卷，生产默认初始化单库。

启动、配置和切换命令见 [单体部署](../operations.md#单体部署)。

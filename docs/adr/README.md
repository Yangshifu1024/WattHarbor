# 架构决策记录

本目录记录**难以逆转**、**无上下文时反直觉**且**源于真实权衡**的决策。ADR 记录取舍及理由，维护规则见 [AGENTS.md](../../AGENTS.md#规则与资料入口)。

文件命名为 `NNNN-<slug>.md`，`NNNN` 从 `0001` 起连续编号，中间不跳号——编号连续本身就是索引，读者靠它发现「中间缺了一篇」，而不是以为某条决策不存在。目录里不另建迁移对照表，那类表会自己漂；追踪由 git 历史承担。

## 文件格式

每份决策记录以 YAML front matter 开头，`status` 标注位置固定在第一块：

```markdown
---
status: accepted
---

# 标题写清决策本身，不是主题

背景、取舍、代价，以及被否决的替代方案。
```

`status` 的取值是固定集合，不是自由文本：

| 取值 | 含义 |
| --- | --- |
| `proposed` | 已提出，尚未决定是否采纳 |
| `accepted` | 已采纳，当前有效 |
| `rejected` | 已否决，不采用；被否决的理由有记录价值时写在正文 |
| `deprecated` | 曾有效、现已不适用；文件保留供追溯 |
| `superseded` | 已被后续决策取代，正文须写明取代它的新编号 |

机器认的那一份是 [check-rules.mjs](../../scripts/rules/check-rules.mjs) 的 `ADR_STATUSES`，上表是给人看的；增删取值要同时改两处。`superseded` 该写明的新编号**本条无对应检查**，靠人工核对。

## 判定

`node tasks.mjs check-rules` 判定文件名不合约定、编号重号、编号断号、缺 `status` 标注、`status` 取值不在集合内五类问题，并点名涉及的文件。目录说明 `README.md` 不是决策记录，检查会跳过它。

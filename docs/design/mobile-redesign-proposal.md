# 电港充电移动端设计提案

2026-11-28 · 四页方案已确认并在 Taro 双端实现。[打开交互样稿](mobile-redesign-preview.html) · [查看前期案例调研](mobile-redesign-references.md)

## 页面与导航

| 页面 | 从上到下的信息顺序 | 主要交互 | 底栏高亮 |
| --- | --- | --- | --- |
| 首页 | 顶部广告、充电站列表。每行显示站点图、站名、地址及已知空闲端口数。 | 点站点进入该站的设备列表；滚动到底自动续载。 | 首页 |
| 充电站 | 顶部广告、当前站名与地址、设备列表。显示设备名、完整编号及空闲 / 总端口数。 | 点设备进入其端口与套餐页；返回首页继续选站。 | 首页 |
| 设备 | 顶部广告、站点和设备标识、端口矩阵、套餐与提交按钮。 | 先选空闲端口，再按金额、时长或电量选套餐。提交前核对站点、设备、端口和预付金额。 | 首页 |
| 我的 | 微信昵称、已绑定手机号、钱包余额、充电订单和全部账户服务。 | 服务入口直接展示；开发环境可从资料区切换测试账号。 | 我的 |

底栏固定为「首页 / 扫码 / 我的」。中间的扫码直接发起识别。取消后保留原页及其高亮。识别成功进入设备页，高亮首页。设备码打开端口列表，空闲插座码预选该端口。小程序使用相机，普通 H5 依现有能力提供编号输入。文件样稿以弹层演示两种入口。

## 视觉规格

- 大面留白，标题与主操作使用石墨黑 `#13191C`，分隔线使用银灰 `#DBE1E3`；冰蓝 `#C3F1FB` 用于当前导航及选择提示。端口状态同时显示文字，金额和端口号使用等宽数字。
- 前三页的顶部广告带「广告」标识。首页广告突出品牌，站点页与设备页压低其高度，让设备列表或端口尽早进入首屏。广告使用本地生成的硬件产品视觉，站点缩略图使用本地生成的建筑场景图，均为样稿素材。
- 首页列表用缩略图区分站点；设备列表改用设备符号与编号；设备页用矩阵区分端口，用标签页区分套餐模式。手机底栏预留安全区，「我的」延续同一套字体和间距。

## 交互验收与业务边界

1. 依次进入首页、站点、设备，页面列表与上一步选择一致。三个页面均显示广告，只有首页导航高亮。从任一页面进入「我的」，仅「我的」高亮。
2. 设备离线或端口使用中、故障时不能选用。切换端口或套餐模式后清除已选套餐。金额单位为分，显示为元。
3. 支付时核对实物编号与预付金额。模拟支付后显示设备启动确认中，并可在「我的」查回该订单。生产实施按服务端证据分别显示支付、启动、停止、结算与退款状态。
4. 首发保留钱包充值与在线卡范围。订单退款从对应充电订单查看，余额退款从钱包进入。账户、广告、图片、站点、余额与款项均为示例；正式广告素材、投放数据源和广告内容由运营提供。
5. 首次打开的手机窄屏应可见广告及列表首项；长列表可滚动，底栏持续可操作。开发时复用现有 Taro 路由与控制器，按真实可用性消费套餐与统计字段。缺少可靠统计时，数量显示为「—」。

## 列表数据

站点列表项和站点详情同时提供数字主键 `id` 和十进制字符串 `id_text`。JavaScript 客户端用 `id_text` 作为列表标识和详情路由参数，避免大整数舍入导致串站。

站点列表项和详情的每台设备均返回 `available_port_count`、`total_port_count`。总数取网关未删除端口数，可用数要求中央设备启用，并满足扫码端口的厂商与设备启用、近期可见、空闲且无订单占用规则。列表汇总本站未删除且未退役的设备，空站返回两个 0。若任一设备缺少对应计数，汇总的该项返回 `null`。

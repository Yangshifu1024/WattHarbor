# 移动端充电体验调研

本次查阅了校园充电服务指南、两轮车充电小程序开发商案例、充电运营商帮助中心和微信支付文档，并核对了 WattHarbor 的双端适配代码。以下为公开资料与源码走查。使用频率、现场完成时间和用户偏好仍需通过任务测试获得。

| 场景 | 一手资料中的事实 | 对 WattHarbor 的设计建议 |
| --- | --- | --- |
| 人已经在插座前 | 北京邮电大学后勤部的电动自行车充电指南说明，用户可以从「附近设备」查看插座是否空闲，也可以直接扫插座上的码进入付款信息页。中网充还允许从故障插座扫码报修。[校方充电服务指南](https://hq.bupt.edu.cn/info/1006/1098.htm) | 首页给「扫码充电」和「查找站点」不同入口。扫到端口就显示站点、设备、插座号及可用状态；扫到整台设备再选插座。故障时沿用已识别的设备进入报修。 |
| 码扫不出来 | 广州优匠科技介绍，其云慧傲停电瓶车小程序同时支持输入充电插座编号和扫描设备二维码。[优匠产品案例](https://www.ujtek.cn/case/102) | 将「输入设备编号或端口码」放在扫码动作旁。手输和扫码共用识别结果、资费与确认页；让用户用桩身印刷的号码核对目标。 |
| 离开设备后查单 | 汽车充电运营商 ChargePoint 将可用状态放在站点详情，在充电记录展示费用和电量，并区分完成和中断提醒。[ChargePoint 官方说明](https://www.chargepoint.com/drivers/support/faqs/what-can-i-do-chargepoint-app) | 借鉴状态与费用的分层。回到首页先看到当前订单，订单详情先显示当前状态以及用户能做的事，结算后再突出实付金额与电量。提醒渠道另有平台依赖。 |
| 微信收银台返回 | 微信支付区分成功、取消及失败回调，并要求由服务端查单或支付成功通知确认付款结果。[微信支付商户文档](https://pay.wechatpay.cn/doc/v3/merchant/4012791898) | 对待确认款项显示「正在确认支付结果」和「查看订单」，按业务结果分别显示充值到账、等待设备启动或充电中。用户返回页面时沿用原订单查询，减少重复支付。 |

**双端验收边界。** 当前适配器在微信小程序调用扫码接口，普通 H5 使用设备编号或端口码输入。H5 支付仅支持开发模拟。可在浏览器验证「输入编号 → 确认端口」以及模拟支付后的查单与状态恢复；微信扫码、拒绝相机权限、真实收银台返回和真设备启动应分别留待环境就绪后验证。[项目平台适配器](../../frontend/miniprogram/src/runtime/platform.ts) · [扫码控制器](../../frontend/miniprogram/src/pages/scan/scan.controller.js)

# 审查后续分诊

目标：保留旧审查未解决的问题，不把推测当缺陷。决定推进的事项再拆独立工单；旧审查的修复流水和历史执行记录留在 Git 历史。

| 事项 | 依赖 | 分诊完成标准 |
| --- | --- | --- |
| 后台深分页成本 | 代表性数据规模和查询负载 | 记录典型查询的执行计划、延迟与连接等待，再决定是否限制深页或采用游标。 |
| 导出长事务与锁等待 | 代表性导出数据、慢存储场景 | 测量生成耗时和锁等待；若拆事务，验收生成所有权、权限重验、取消和未知提交结果下的产物清理。 |
| 管理员代登记 MFA | 产品和安全负责人确认目标账号的持有证明要求 | 明确现行流程是否调整及验收标准，不把待决策项写成已确认缺陷。 |
| 历史账务核对 | 明确审计范围、账务凭证和负责人 | 给出只读核对结果；补账不等于已更正既有金额，异常处置另立工单。 |
| 规则自动检查 | 以当前 `AGENTS.md` 和规则检查器为准 | 分别决定是否补做链接与锚点校验、枚举防漂移；若推进，明确覆盖范围与历史例外，不恢复旧目录。 |

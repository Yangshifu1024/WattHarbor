# 规则层入口

本文件是本仓库规则层的**单一入口**。规则按类目各有一处落点，不在多处重述；要找某条规则先来这里，再按类目进入。

规则分两层：

- **人读层**（本目录、[docs/adr/](../adr/README.md) 与 [GLOSSARY.md](../../GLOSSARY.md)）承载解释、意图，以及机器判不了的约束。
- **agent 执行层**（[AGENTS.md](../../AGENTS.md)）只承载可执行的检查与指向检查的指针。

检查代码在 `scripts/rules/`，判定入口与覆盖范围见 [验证入口](verification.md)。

## 类目与唯一落点

| 类目 | 落点 | 承载什么 |

| 架构边界与依赖 | [architecture.md](architecture.md) | 目录归属、依赖方向、表与用例的边界。可判定部分转成检查，判不了的原地标注无对应检查。 |
| 业务不变量 | [business-invariants.md](business-invariants.md) | 计量、资金、权限与异步恢复的业务规则。凡能写成断言的，散文处只留解释与指针。 |
| 架构决策 | [docs/adr/](../adr/README.md) | 难以逆转且无上下文时反直觉的取舍，编号连续、每份带状态标注。 |
| 术语边界 | [GLOSSARY.md](../../GLOSSARY.md) | 领域术语的唯一权威定义；只定义边界，不承载规则。 |
| 验证入口 | [verification.md](verification.md) | 只列检查命令与各自覆盖什么，不复制规则内容。 |

## 冻结与归档

- **冻结**：规则已迁入新层的旧文档标记为「已冻结、只读」。内容仍可读可查，但不再接受新增或修改规则。清单登记在 `scripts/rules/check-rules.mjs` 的 `FROZEN_DOCUMENTS`，由 `node tasks.mjs check-rules` 判定声明是否在位、措辞是否齐全、链接是否指向本入口且可解析。清单里登记的文件被删除时检查同样报红，逼着迁移票同步移除条目。
- **归档**：已完成的批次流水与历史快照放在 [plans/archive/](plans/archive/README.md)，与活跃计划物理分离。归档只放历史，活跃规则不写入归档。

## 新增一条规则怎么落位

1. 先定类目，按上表找到唯一落点；找不到合适落点说明类目划分有缺口，应当补类目而不是随手放进现有文件。
2. 能写成断言的写成断言；写不成断言的（依赖方向、归属、意图这类机器判不了的）在落点原地标注「本条无对应检查」，不要假装它可验证。
3. 在 agent 执行层加一行指向该检查的指针。

这套结构本身也是断言。`node tasks.mjs check-rules` 登记了六条文档层不变量，**当前只实现了冻结声明这一条**，其余五条已登记但尚未实现断言，报告里逐条标注「尚未实现」——计数写在摘要里，不计入已验证。哪几条已实现以 [验证入口](verification.md) 与检查的实际输出为准，不以本文为准。
